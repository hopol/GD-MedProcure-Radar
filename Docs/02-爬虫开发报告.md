## 1. 目标数据源分析

通过实际访问和逆向分析，确定了两个主要数据源的技术特征：

### 1.1 广东省政府采购网 (GDGPO)

| 项目 | 详情 |
|------|------|
| **实际 URL** | `https://gdgpo.czt.gd.gov.cn`（原 ccgp-guangdong.gov.cn 已重定向） |
| **技术栈** | Vue.js 2 SPA + Element UI |
| **渲染方式** | 纯前端渲染（SPA），所有数据通过 REST API 加载 |
| **列表 API** | `GET /gpcms/rest/web/v2/info/selectInfoForIndex` |
| **详情 API** | `GET /gpcms/rest/web/v2/info/getInfoById` |
| **分页参数** | `currPage`（页码，从 1 开始），`pageSize`（每页条数） |
| **响应结构** | `{ code: 200, data: { rows: [...], total: N } }` |
| **关键字段** | `noticeId`, `title`, `noticeTime`, `regionName`, `purchaser`, `agency`, `budget`（元为单位字符串）, `openTenderCode`, `catalogueNameList`（逗号分隔字符串） |

**重要发现**：
- `catalogueNameList` 返回的是逗号分隔的字符串（如 `"临床检验设备,物理治疗"`），非数组
- `budget` 返回的是以**元**为单位的字符串（如 `"1311000.0000"`），需除以 10000 转万元
- `purchaseNature=1` 可筛选"货物"类采购（含医疗设备）

### 1.2 广东省公共资源交易平台 (GDGGZY)

| 项目 | 详情 |
|------|------|
| **实际 URL** | `http://ygp.gdzwfw.gov.cn`（原 gdggzy.org.cn 已失效） |
| **技术栈** | Vue.js 3 SPA |
| **渲染方式** | 纯前端渲染（SPA），Hash 路由模式 |
| **搜索 API** | `POST /ggzy-portal/search/v2/items` |
| **分页参数** | `pageNo`（页码），`pageSize`（每页条数） |
| **响应结构** | `{ errcode: 0, data: { pageData: [...], total: "N" } }` |
| **关键字段** | `docId`, `noticeTitle`, `projectOwner`, `projectCode`, `regionName`, `publishDate`（YYYYMMDDHHmmss），`datasetName`, `pubServicePlat` |

**重要发现**：
- API 响应使用 `errcode`（整数 0）表示成功，非 `code`
- 空关键词搜索返回 0 结果，**必须提供关键词**才能获取数据
- `publishDate` 格式为 `YYYYMMDDHHmmss`（14位），需转换为 `YYYY-MM-DD`
- `noticeTitle` 可能包含 HTML 高亮标签（`<span>`），需清洗
- 部分记录的字段可能为 `null`，需做防御性处理

## 3. 核心架构设计

### 3.1 类继承结构

```
BaseScraper (抽象基类)
    ├── GDGPOScraper     # 广东省政府采购网 (GET API)
    └── GDGGZYScraper    # 广东省公共资源交易平台 (POST API)

PlaywrightFallbackScraper  # 独立备选类（非继承，API 变更时使用）
```

### 3.2 BaseScraper 基类职责

| 功能 | 实现方式 |
|------|----------|
| HTTP 请求封装 | `requests.Session` + `HTTPAdapter` 自动重试 |
| 请求限速 | `_polite_delay()` 随机 1~3 秒间隔 |
| 请求头伪装 | 5 个 User-Agent 随机轮换 |
| 医疗设备过滤 | `is_medical_related()` 基于 27 个关键词匹配 |
| 品目分类 | `classify_category()` 基于 8 大类目关键词映射 |
| 唯一 ID 生成 | `make_project_id()` 基于 source:id 的 MD5 前 16 位 |

### 3.3 数据采集流程

```
main.py 入口
    │
    ├─ 解析命令行参数 (--test, --days, --source, --playwright, --no-merge)
    │
    ├─ 初始化日志 (logging.basicConfig)
    │
    ├─ 遍历所有爬虫实例
    │   └─ 对每个爬虫:
    │       ├─ scraper.crawl(start_date, end_date, max_pages)
    │       ├─ 保存原始快照 → data/raw/{timestamp}_{source}.json
    │       └─ 收集统计信息
    │
    ├─ 跨源去重 (deduplicate)
    │   ├─ 策略 1: project_id 精确匹配
    │   └─ 策略 2: project_no 项目编号匹配
    │
    ├─ 增量合并 (merge_with_existing)
    │   ├─ 加载 data/procurements.json 已有数据
    │   ├─ 新记录追加，已有记录按字段合并更新
    │   └─ 旧记录保留
    │
    ├─ 按发布日期倒序排列
    │
    ├─ 保存最终数据 → data/procurements.json
    │
    └─ 输出统计报告（地区分布、品目分布、日期范围）
```

## 4. 防爬策略与应对措施

| 防爬手段 | 实现方式 | 代码位置 |
|----------|----------|----------|
| **User-Agent 轮换** | 5 个主流浏览器 UA 随机选择 | `config.py: USER_AGENTS` |
| **请求限速** | 随机 1~3 秒间隔，避免触发频率限制 | `BaseScraper._polite_delay()` |
| **Referer 伪造** | 每个数据源配置正确的 Referer 头 | `config.py: GDGPO_HEADERS` |
| **自动重试** | `urllib3.Retry` 处理 429/5xx 错误，指数退避 | `BaseScraper._build_session()` |
| **429 特殊处理** | GDGGZY 触发 429 时等待 30 秒后重试 | `GDGGZYScraper.crawl()` |
| **Session 复用** | `requests.Session` 保持 TCP 连接和 Cookie | `BaseScraper.__init__()` |
| **请求超时** | 30 秒超时，避免长时间阻塞 | `config.py: HTTP_CONFIG` |

## 5. 异常处理机制

| 异常场景 | 处理方式 |
|----------|----------|
| 网络超时 | `requests.Timeout` → 自动重试（最多 3 次） |
| HTTP 错误 (4xx/5xx) | `raise_for_status()` → 记录日志 → 跳过当前页 → 继续下一页 |
| 429 频率限制 | 等待 30 秒后重试一次，仍失败则跳过 |
| API 响应结构变更 | `code`/`errcode` 双重检查 → 抛出 ValueError → 记录日志 |
| 字段解析失败 | 单条记录 try/except → 记录 WARNING → 跳过该条继续 |
| JSON 解析失败 | 被 requests 异常捕获 → 重试 |
| 数据文件写入失败 | 主函数顶层异常 → 日志记录 → 退出码非 0 |

## 7. 命令行用法

```bash
# 正常采集（默认近 30 天，全部数据源）
python -m scraper

# 测试模式（仅 2 页，快速验证）
python -m scraper --test

# 采集近 7 天
python -m scraper --days 7

# 仅采集指定数据源
python -m scraper --source gdgpo
python -m scraper --source gdggzy

# 使用 Playwright 备选方案
python -m scraper --playwright

# 不与历史数据合并（仅保存本次）
python -m scraper --no-merge

# 调试日志
python -m scraper --log-level DEBUG
```

## 9. Playwright 备选方案

`PlaywrightFallbackScraper` 提供了浏览器渲染的备选采集方式：

- **触发场景**：当主 API 结构发生重大变更（字段缺失、接口失效）时手动启用
- **工作原理**：启动 Chromium 浏览器 → 打开列表页 → 通过 `page.on("response")` 拦截 API 响应 → 复用 GDGPOScraper 的解析逻辑
- **优势**：即使前端 JS 变更，只要底层 API 不变，拦截方式仍然有效
- **安装**：`pip install playwright && playwright install chromium`
