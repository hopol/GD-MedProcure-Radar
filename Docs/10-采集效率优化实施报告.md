## 一、实施背景

GitHub Actions 免费账户每月仅有 2,000 分钟额度。项目当前的采集流程存在严重效率问题：
- 每次采集耗时约 **5 分钟**（纯爬虫时间）
- 每天运行 2 次 × 7 天 = **每周 14 次**
- 大量冗余等待（过长超时、过多重试、串行执行）

基于 `Docs/09` 报告的分析结论，本次实施覆盖 **P0（立即实施）+ P1（短期优化）+ P2（中期改善）** 三个优先级的全部优化方案。

## 三、详细实施记录

### 3.1 P0-A：HTTP 参数全面优化

**文件**: `scraper/config.py`

| 参数 | 修改前 | 修改后 | 变化 | 效果 |
|------|--------|--------|------|------|
| `connect_timeout` | 60s | 20s | -67% | 快速失败，减少无效等待 |
| `read_timeout` | 120s | 30s | -75% | 超时快速释放 |
| `timeout` | (60, 120) | (20, 30) | - | 元组同步更新 |
| `max_retries` | 5 | 3 | -40% | 减少无效重试次数 |
| `retry_delay` | 5s | 3s | -40% | 缩短重试间隔基数 |
| `request_delay` | (2, 5)s | (0.8, 1.5)s | -70% | 大幅降低请求间隔 |
| `page_size` | 20 | 50 | +150% | 减少翻页次数 60% |
| `detail_delay` | 不存在 | (0.3, 0.8)s | 新增 | 详情 API 专用短延迟 |

**理论节省**：列表页每次请求节省约 2.5~3.5 秒，详情请求节省约 2~4.5 秒。

### 3.2 P0-B：GDGGZY 关键词精简

**文件**: `scraper/gd_scraper.py` (GDGGZYScraper.crawl)

```python
# 修改前：4 个关键词
search_keywords = ["医疗设备", "医疗器械", "医用设备", "医疗仪器"]

# 修改后：2 个关键词（"医疗设备"已涵盖后两者的搜索结果）
search_keywords = ["医疗设备", "医疗器械"]
```

**效果**：
- 关键词搜索轮次从 4 次减至 2 次
- 减少 50% 的列表页请求数
- 预计节省 **40~80 秒**（取决于每个关键词的页数）

### 3.3 P0-C：详情采集并发化

**文件**: `scraper/gd_scraper.py` (GDGPOScraper.crawl)

**修改前**：串行逐条获取，每条加 2~5 秒延迟
```python
for item in items:
    detail = self.fetch_detail(nid)
    item.content = text[:2000]
    self._polite_delay()  # 每条 2~5 秒
```

**修改后**：ThreadPoolExecutor 3 线程并发 + 0.3~0.8 秒短延迟
```python
with ThreadPoolExecutor(max_workers=3) as pool:
    futures = {pool.submit(_fetch_one, item): item for item in items}
    for future in as_completed(futures):
        item, content = future.result()
        if content:
            item.content = content
```

**新增方法**: `BaseScraper._detail_delay()` — 详情 API 专用短延迟

**效果**（假设 20 条详情）：
- 修改前：20 × (2~5s + 请求时间) ≈ 80~140 秒
- 修改后：20/3 × (0.3~0.8s + 请求时间) ≈ 15~25 秒
- **节省约 60~115 秒**

### 3.4 P0-D：双数据源并行执行

**文件**: `scraper/main.py`

**修改前**：for 循环串行执行两个爬虫
```python
for scraper in scrapers:
    items = scraper.crawl(...)
```

**修改后**：ThreadPoolExecutor 并行执行
```python
with ThreadPoolExecutor(max_workers=len(scrapers)) as pool:
    futures = {pool.submit(_run_scraper, s): s for s in scrapers}
    for future in as_completed(futures):
        scraper, items = future.result()
```

**效果**：
- 两个数据源同时运行，总耗时 = max(GDGPO时间, GDGGZY时间)
- 而非原来的 GDGPO时间 + GDGGZY时间
- **预计节省 30~50% 的总采集时间**

### 3.5 P1-E：依赖拆分

**新建文件**: `scraper/requirements-core.txt`

```
requests>=2.31.0
urllib3>=2.0.0
```

**对比原版** `requirements.txt`（18 行）：去除了 beautifulsoup4、pandas、playwright、lxml

**效果**：
- pip install 从安装 6+ 包（含编译）降至仅 2 个纯 Python 包
- 预计节省 CI 环境准备时间 **15~30 秒**
- 减少缓存体积和潜在的安装失败风险

### 3.6 P1-F：Cron 工作日限定

**文件**: `.github/workflows/update-data.yml`

```yaml
# 修改前：每天运行
- cron: '0 0 * * *'
- cron: '0 6 * * *'

# 修改后：仅工作日运行
- cron: '0 0 * * 1-5'    # 周一至周五
- cron: '0 6 * * 1-5'    # 周一至周五
```

**效果**：
- 每周运行次数：14 次 → 10 次（减少 29%）
- 每月节省约 **8 次 Actions 运行**
- 周末医疗设备采购公告发布量极少，不影响数据完整性

### 3.7 P2-G：部署流程去冗余

**文件**: `.github/workflows/deploy-pages.yml`

```yaml
# 修改前：安装不必要的 requests
pip install -q requests 2>/dev/null
python3 scripts/fix_data_urls.py

# 修改后：直接使用标准库运行
python3 scripts/fix_data_urls.py
```

**分析**：`fix_data_urls.py` 和 `build_index.py` 均只使用 Python 标准库（json, os, re, datetime, pathlib），无需安装任何第三方包。
