## 四、搜索引擎设计

### 4.1 架构概述

采用**双层搜索策略**，兼顾 FlexSearch 的高效索引和中文子串精确匹配：

```
用户输入 → FlexSearch Index 搜索（英文/数字/拼音前缀）
         → 中文子串匹配补充（CJK 字符 fallback）
         → 合并结果 → 应用筛选 → 分页展示
```

### 4.2 FlexSearch Index 模式

使用 `FlexSearch.Index`（单字段独立索引）而非 `FlexSearch.Document`（多字段文档索引），原因：

- `Document` 模式对中文长字符串的分词不够精准
- `Index` 模式允许对每个字段独立控制搜索权重
- 更容易调试和维护

```javascript
const FIELDS = ['project_name', 'project_no', 'hospital', 'agency', 'category', 'raw_category'];
FIELDS.forEach(field => {
  const idx = new FlexSearch.Index({ tokenize: 'forward', resolution: 9, cache: 100 });
  indexDocs.forEach(doc => idx.add(doc.id, doc[field] || ''));
  searchIndexes[field] = idx;
});
```

### 4.3 中文子串匹配

FlexSearch 的 `forward` 分词器基于空白符分词后生成前缀 token。对于无空格的中文文本（如"阳江市人民医院"），会生成完整前缀链（"阳"、"阳江"、"阳江市"...），但当查询词不是从字段首字符开始的子串时可能遗漏。

解决方案：当搜索包含中文字符时，额外进行线性子串匹配作为补充：

```javascript
if (matchedIds.size === 0 || /[\u4e00-\u9fff]/.test(query)) {
  this.allDocs.forEach(doc => {
    const haystack = [doc.project_name, doc.project_no, doc.hospital, ...].join(' ');
    if (haystack.includes(query)) matchedIds.add(doc.id);
  });
}
```

对于 ~100 条记录的量级，线性扫描的开销可忽略不计。

### 4.4 数据加载流程

```
init()
  ├── fetch('./data/search-index.json')     → 搜索索引文档
  ├── fetch('./data/aggregations.json')     → 聚合统计数据
  └── fetch('./data/procurements.json')     → 采购详情数据
       │
       ├── 构建 docLookup (id → doc)
       ├── 构建 FlexSearch Index (6 个字段)
       ├── 渲染筛选下拉菜单
       └── 初始显示全部记录
```

## 五、Alpine.js 状态管理

### 5.1 核心状态

```javascript
{
  loading: true,              // 数据加载状态
  allDocs: [],                // 全部索引文档
  fullData: {},               // 详情查找表 { id: {...} }
  aggregations: {},           // 聚合统计
  searchIndexes: {},          // FlexSearch 索引实例 { field: Index }
  searchQuery: '',            // 搜索关键词
  filterRegion: '',           // 地区筛选值
  filterCategory: '',         // 类目筛选值
  filteredResults: [],        // 当前筛选结果
  currentPage: 1,             // 当前页码
  pageSize: 20,               // 每页条数
  stats: { total, lastUpdate }
}
```

### 5.2 计算属性

| 属性 | 说明 |
|------|------|
| `totalPages` | `Math.ceil(filteredResults.length / pageSize)` |
| `paginatedResults` | `filteredResults.slice(start, start + pageSize)` |
| `visiblePages` | 当前页前后各 2 页的页码数组 |

### 5.3 关键方法

| 方法 | 触发时机 | 功能 |
|------|---------|------|
| `init()` | 页面加载 | 并行获取数据，构建索引 |
| `doSearch()` | 搜索输入 / 筛选变更 | 双层搜索 + 筛选 |
| `applyFilters()` | 下拉菜单变更 | 委托 `doSearch()` |
| `resetFilters()` | 重置按钮 | 清空所有条件，显示全部 |
| `goPage(n)` | 分页按钮 | 翻页并滚动到顶部 |
| `highlightText(text)` | 渲染卡片 | 搜索关键词黄色高亮 |
| `formatBudget(val)` | 渲染金额 | 千分位格式化 |
| `categoryColor(cat)` | 渲染类目 | 返回对应 TailwindCSS 类 |

## 七、GitHub Actions 部署更新

### 7.1 简化部署流程

原先通过 Vite 构建 → `npm ci` + `npm run build`，现简化为：

```yaml
- name: 组装部署目录
  run: |
    mkdir -p dist/data
    cp frontend/index.html dist/
    cp frontend/public/data/*.json dist/data/
```

无需 Node.js 环境，纯文件复制。

### 7.2 数据路径回退策略

```
优先: frontend/public/data/*.json   （build_index.py 预生成）
回退: data/*.json                    （爬虫直接输出）
兜底: 运行 build_index.py 构建       （如果 search-index.json 缺失）
```

### 8.2 已知限制

- **FlexSearch 中文分词**：CJK 文本无空格分隔，`forward` 模式仅能匹配字段起始子串。已通过线性子串匹配补充解决
- **TailwindCSS CDN**：`cdn.tailwindcss.com` 仅适用于开发环境，生产部署应替换为预编译 CSS
- **数据量扩展**：当前 ~50 条记录，线性搜索无压力。如数据量增长到 10,000+，可考虑引入 Web Worker 进行异步搜索
