# 07 - 详情链接修复与公告内容采集

> 粤采雷达 GD-MedProcure-Radar
> 日期：2026-06-07

---

## 一、问题描述

### 问题 1：详情页链接几乎全部错误

**现象：** 前端"查看详情"链接点击后无法打开正确的公告页面。

**根因：** GDGPO（广东省政府采购网）的 URL 模板使用了错误的路由和参数名：

| 项目 | 修改前（错误） | 修改后（正确） |
|------|---------------|---------------|
| 路由路径 | `/maincms-web/articleDetail` | `/maincms-web/noticeGd` |
| 参数名 | `?noticeId=` | `?id=` |
| 完整模板 | `...articleDetail?noticeId={notice_id}` | `...noticeGd?id={notice_id}` |

经实际验证，使用 `articleDetail?noticeId=` 会返回 4001 内部错误，只有 `noticeGd?id=` 才能正常加载。

GDGGZY（公共资源交易平台）的 URL 模板格式本身正确，无需修改。

### 问题 2：缺少公告正文内容

**现象：** 用户只能看到标题、编号等元信息，想了解详细内容必须点击"查看详情"跳转到外部网页。

**改进：** 新增 `content` 字段，通过调用 GDGPO 的详情 API 自动采集公告正文内容，在前端以可折叠面板展示。

## 二、修改内容

### 2.1 修复 GDGPO 详情 URL 模板

**文件：** `scraper/config.py`

```python
# 修改前
"detail_url_template": "https://gdgpo.czt.gd.gov.cn/maincms-web/articleDetail?noticeId={notice_id}"

# 修改后
"detail_url_template": "https://gdgpo.czt.gd.gov.cn/maincms-web/noticeGd?id={notice_id}"
```

### 2.2 新增 `content` 字段

**文件：** `scraper/gd_scraper.py`

在 `ProcurementItem` 数据模型中新增：

```python
content: str = ""    # 公告正文内容（纯文本摘要）
```

### 2.3 GDGPO 爬虫采集公告正文

**文件：** `scraper/gd_scraper.py`

在 GDGPO 列表页采集完成后，新增详情采集阶段：

```
列表采集完成
    ↓
遍历每条记录，调用 fetch_detail(notice_id) 获取详情 API
    ↓
提取 description 字段（HTML 正文）
    ↓
去除 HTML 标签 → 纯文本
    ↓
截取前 2000 字 → 写入 item.content
```

**特性：**
- 每条详情请求之间有礼貌延迟（2~5 秒随机）
- 单条失败不影响其他记录的采集
- 每 5 条输出一次进度日志
- 可通过 `--no-content` 命令行参数跳过（加速测试）

### 2.4 新增 `--no-content` 命令行参数

**文件：** `scraper/main.py`

```bash
python -m scraper                     # 默认：采集列表 + 正文
python -m scraper --no-content        # 跳过正文采集（更快）
python -m scraper --test --no-content # 快速测试
```

### 2.5 搜索索引包含正文摘要

**文件：** `scripts/build_index.py`

搜索索引文档新增 `content` 字段（截取前 300 字），供前端卡片展示。

### 2.6 前端可折叠公告内容面板

**文件：** `frontend/index.html`

每条结果卡片底部新增：

```
┌─ 项目名称 ─────────────────────────── 类目/金额 ─┐
│ 编号 | 医院 | 地区 | 日期                    详情→ │
├───────────────────────────────────────────────────┤
│ ▸ 查看公告内容  （仅在有 content 时显示）         │
│ ┌─────────────────────────────────────────────┐   │
│ │ 公告正文纯文本内容...                         │   │
│ │ （最大高度 240px，超出可滚动）                │   │
│ └─────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────┘
```

**技术实现：**
- 使用 Alpine.js `x-data="{ expanded: false }"` 控制展开状态
- 使用 `@alpinejs/collapse` 插件实现平滑折叠动画
- `x-show="item.content"` 仅在有内容时显示展开按钮

## 三、配置项说明

**文件：** `scraper/config.py` → `HTTP_CONFIG`

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `fetch_content` | bool | `True` | 是否在采集时调用详情 API 获取公告正文 |

可在 `main.py` 中通过 `--no-content` 参数覆盖为 `False`。

---

## 四、数据流

```
GDGPO 列表 API (selectInfoForIndex)
    ↓
返回 noticeId, title, purchaser, budget 等字段
    ↓
GDGPO 详情 API (getInfoById?id={noticeId})
    ↓
返回 description 字段（HTML 正文）
    ↓
去除 HTML 标签 → 纯文本 → 截取前 2000 字
    ↓
写入 ProcurementItem.content
    ↓
build_index.py → search-index.json（前 300 字摘要）
    ↓
前端 index.html → 可折叠面板展示
```

## 六、使用说明

### 完整采集（列表 + 正文）

```bash
python -m scraper --days 7
```

采集速度：约 12 条/分钟（含正文采集），50 条数据约需 5 分钟。

### 快速采集（仅列表，跳过正文）

```bash
python -m scraper --no-content
```

采集速度：约 200 条/分钟，适合首次部署或快速测试。

### 采集后重建索引

```bash
python scripts/build_index.py
```
